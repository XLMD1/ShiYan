需求汇总 & 系统架构方案

Django + Vue 3 · K-Means + 线性回归 · 双数据集 · 多用户 · 可配置图表

技术栈确认

后端框架 Django + Django REST Framework
前端框架 Vue 3 + Vite + ECharts
数据分析 Pandas + scikit-learn (K-Means + LinearRegression)
数据集 Mall Customers (演示) + California Housing (深度)
用户系统 注册/登录 + 独立数据空间 + 历史记录检索
图表 用户可配置：类型/轴/颜色，6种图表起

三种架构方案对比

A

前后端完全分离

Django 纯 API + Vue SPA 独立开发，通过 REST 通信

优势

  • 5-6人团队可并行开发，后端/前端各自独立
  • API 接口清晰，Swagger 自动文档便于对接
  • 部署时 Vue build 放 Django static 即可统一服务

挑战

  • 需要处理 CORS（开发阶段）
  • 需要维护 API 接口约定
B

Django 模板内嵌 Vue 组件

Django 渲染页面，Vue 作为增强组件嵌入模板

优势

  • 单项目结构，Django 模板直出，部署最简单
  • 不需要 CORS / JWT 配置，Session 认证直用

挑战

  • 前后端代码耦合，不便于团队并行开发
  • ECharts 动态交互受限于模板内组件通信方式
C

Nuxt 3 全栈（Django 退为计算引擎）

Nuxt 处理 Web 层，Django 仅作为数据分析计算服务

优势

  • Vue 生态最现代方案，SSR/CSR 自动切换
  • 前后端同构，开发体验好

挑战

  • 新技术栈，团队学习成本高
  • Django 的认证/ORM 优势被削弱
  • 对课程实验来说过度设计

推荐方案 A：前后端完全分离

最匹配 5-6人团队并行开发 的需求。后端3人（Django API + 数据分析逻辑），前端2-3人（Vue组件 + ECharts）。接口通过 DRF 的 Browsable API 实时调试，Swagger 自动生成文档。最终部署时 Vue build 产物放入 Django static 目录，统一由一个 Django 进程服务。
