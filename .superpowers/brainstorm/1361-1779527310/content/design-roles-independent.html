设计修订：4 人独立模块分工

每人一个 Django App + 对应的 Vue 页面/组件，代码不交叉，可独立 MR

阶段1（先行）

角色 A：项目基础 + 认证模块

Django App： accounts

模型： 无新增（用 Django User）

API： register / login / me

Vue 页面： LoginView, RegisterView

Vue 组件： NavBar

基础设施： Django 项目骨架、Vue 项目骨架、路由守卫、Axios 封装、JWT 配置

先行交付，其他人 fork 此分支
阶段2（并行）

角色 B：数据管理模块

Django App： datafile

模型： Dataset

API： upload / list / detail / preview / delete / export

Vue 页面： DashboardView, UploadView

Vue 组件： FileUploader, DataTable

依赖： 仅依赖 accounts 的 JWT 认证

独立 App + 独立页面，可单独 MR
阶段2（并行）

角色 C：清洗+分析模块

Django App： analysis

模型： AnalysisTask, ChartConfig

Pure Python： cleaning.py, clustering.py, regression.py

API： clean / stats / kmeans / regression / chart-generate / tasks / configs

Vue 页面： CleanView, AnalysisView

Vue 组件： AnalysisParams, StatsCard

依赖： 仅依赖 Dataset 模型（读取文件路径）

独立 App + 独立页面，可单独 MR
阶段2（并行）

角色 D：可视化+历史模块

Django App： 无（纯前端 + 调用 C 的 API）

Vue 页面： VisualizeView, HistoryView

Vue 组件： ChartPanel, ChartConfig（图表选择器+参数面板）

ECharts： 6 种图表渲染+配置面板

响应式布局： 全局 CSS 适配

依赖： 仅依赖 C 的图表 API 格式约定

独立页面，可单独 MR

独立性保障规则

规则 说明
1 一人一 App：每个 Django App 只由一人修改，不跨角色编辑同一个文件
2 Vue 页面/组件不共享：每人的 Vue 页面和组件在自己的目录下，通过路由和 props 对接
3 接口先约定：A 先交付基础骨架 + API 文档，B/C/D 基于约定接口并行开发，不等人
4 Git 分支策略：A 在主分支搭骨架 → B/C/D 各自开 feature 分支 → 分别 MR 合入
5 Pinia Store 也分人：auth (A)、dataset (B)、analysis (C)、chart (D)，各自维护

MR 流程示意

main: A 搭骨架 ──┬── B 分支: feature/datafile ──→ MR#2 合入
         ├── C 分支: feature/analysis ──→ MR#3 合入
         └── D 分支: feature/visualize ──→ MR#4 合入
                       ↓
                    最终集成测试

B/C/D 并行开发，每人只改自己的 App + 自己的 Vue 文件，不会产生合并冲突。
